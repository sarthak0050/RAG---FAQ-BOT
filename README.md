# 📈 GROWW Mutual Fund FAQ Bot

A **facts-only** assistant for five HDFC Direct Growth mutual funds, grounded
exclusively in the **official Groww fund pages**. Every answer is generated by
Mistral from embeddings retrieved over a local ChromaDB store, and **every
answer cites its source** with a last-updated date.

Built as a Learn-in-Public (LIP) challenge for the
[NextLeap](https://www.nextleap.app/) Product Manager Fellowship — with the
product discipline of a PRD behind it: a deliberate, narrow scope so the
factuality and safety guardrails stay enforceable.

> **Live demo:** hosted on Hugging Face Spaces
> ([open the Space](https://huggingface.co/spaces/YOUR_SPACE_NAME) — set the
> `MISTRAL_API_KEY` secret to run it).

## Why this product exists

Retail mutual-fund investors often want quick, **factual** answers — expense
ratio, exit load, minimum SIP, ELSS lock-in, riskometer, benchmark, how to
download a statement. That information exists, but it is scattered across
fund factsheets, scheme documents, FAQs, and regulatory pages on the web.

This bot solves a narrow, precise version of that problem:

- It answers **only from a curated, official-source corpus** (the five Groww
  fund pages).
- It **shows a source link with every answer**, so nothing is asserted without
  a citation.
- It **politely refuses everything outside its scope** — investment advice,
  return comparisons, and funds outside the five — instead of guessing.

The scope is deliberately small (5 funds, factual questions only). Accuracy and
trust were prioritised over topic breadth: **it is better to say "I don't
answer that" than to be confidently wrong about somebody's money.**

## Features

- **Grounded RAG answers** — retrieval over a local vector store; the LLM is
  only allowed to answer from retrieved chunks.
- **Source citation + last-updated date** on every answer.
- **Facts-only intent gate** — detects advice, return/comparison, buy/sell
  language and refuses with a clear, educational message.
- **Out-of-corpus gate** — refuses anything about funds/AMCs outside the five
  covered pages.
- **PII scrubbing** — PAN, Aadhaar, account numbers, OTPs, phone numbers and
  emails are detected and redacted before the query is embedded; a warning is
  shown to the user.
- **Name-aware retrieval** — when the question names one of the five funds,
  its chunks are ranked first and exact fact-fields (e.g. expense-ratio rows)
  are boosted with document-filtered search.
- **Dated-fact handling** — for series like expense ratio, the newest dated
  entry is preferred.
- **Weak-hit rejection** — if retrieval confidence is below threshold, the bot
  refuses rather than hallucinate.
- **Premium fintech UI** — Groww-styled dark theme, example question cards,
  typing indicator, source pills (Streamlit).
- **Fresh corpus, automatically** — a scheduler re-fetches the official pages
  and rebuilds the index only when the source content actually changes
  (see [Scheduler](#scheduler-keeping-the-corpus-fresh)).

## Product decisions & scope

These design choices come from the [PRD](docs/PRD.md) and are enforced in code
(see [architecture](docs/architecture.md)):

| Decision | Why |
|---|---|
| Facts-only; **no advice** (best fund, buy/sell, allocation) | Investment advice needs licenses/context; out of scope at launch |
| **No return computation or comparison** | Returns require NAV histories and disclosure; easy to get wrong |
| **Only 5 HDFC Direct Growth funds** on Groww | Small, verifiable corpus = enforceable guardrails |
| **Only official Groww pages** as sources | One trusted, documented place per fact |
| **One source link per answer** | Simpler and equally honest as multiple links |
| News/factsheets not ingested | Keeps corpus stable and reviewable |
| MiniLM-L6-v2 for embedding (docs **and** questions) | Single, consistent, offline model — fast and cheap |
| Mistral for generation | Lightweight, accurate grounded summaries |
| ChromaDB for retrieval | Tiny footprint, fits Hugging Face Spaces/Render free tiers |

## How it works (architecture)

Two flows: an offline **index** job and an online **ask** path.

```
                         ┌─────────────────────────────────────┐
                         │  Corpus (exclusive, PRD §4.1)       │
                         │  5 Groww HDFC Direct Growth URLs    │
                         └─────────────────┬───────────────────┘
                                           │ fetch (batch, scheduled)
                                           ▼
  ┌──────────────┐  chunks   ┌─────────────┐  vectors  ┌──────────┐
  │ Data loading │──────────▶│  Chunking   │──────────▶│ Embedding│
  └──────────────┘           └─────────────┘  MiniLM   └────┬─────┘
                                                            │
                                                            ▼
                                                     ┌─────────────┐
                                                     │ Vector store│
                                                     │  ChromaDB   │
                                                     └──────┬──────┘
                                                            │ similarity
  ┌──────────────┐ question ┌─────────────┐ q-embed        │
  │ Streamlit UI │─────────▶│  Retrieval  │───────────────▶│
  └──────┬───────┘          └──────┬──────┘                │
         │                         │ top-k + metadata      │
         │                         ▼                       │
         │                  ┌─────────────┐                │
         │                  │ Mistral API │ ◀──────────────┘
         │                  └──────┬──────┘  grounded prompt
         │                         │ ≤3 sentences + 1 citation
         ◀─────────────────────────┘  + "last updated from sources"
```

**Offline index pipeline** (each stage is an independent runnable module):

| Stage | Module | Input → Output |
|---|---|---|
| 1. Loading | `code.loading` | 5 Groww URLs → `data/raw/<fund>.json` (readable text) |
| 2. Chunking | `code.chunking` | raw docs → `data/chunks/<fund>.json` (size 800, overlap 160) |
| 3. Embedding | `code.embedding` | chunks → `data/embeddings/*` (MiniLM-L6-v2, 384-d) |
| 4. Vector store | `code.vector_store` | chunks+vectors → ChromaDB collection `groww_hdfc_faq` |

**Online ask path** (`code.retrieval` + `code.generation` + `code.ui`):

`question → PII scrub → intent gate (advice/returns) → out-of-corpus gate →
embed query → Chroma top-k(12) → fund-name boost + fact-field boost →
dedupe → top-k(5) → Mistral (grounded) → answer + citation + last-updated`

## Tech stack

| Layer | Choice | Why |
|---|---|---|
| Language | Python 3.11 | Entire AI/ML ecosystem, simple to deploy serverlessly |
| UI | Streamlit | Fast chat UI, free Spaces/Community Cloud hosting |
| Ingestion | `requests` + BeautifulSoup/lxml | Official pages only; reads Groww's `__NEXT_DATA__` JSON + visible text |
| Extraction | PyPDF2 (docs), regex/JSON flattening (pages) | Structured + visible text both indexed |
| Chunking | Custom splitter (size 800 / overlap 160) | Keeps chunks under MiniLM's 256-token context; newline-aware breaks |
| Embeddings | `sentence-transformers/all-MiniLM-L6-v2` | 384-d, offline, consistent for queries and docs |
| Vector store | ChromaDB (persistent) | Embedded local store; no external DB needed on free tiers |
| RAG orchestration | `code.retrieval` (custom) | Full control over gates, boosting, refusals |
| Generation | Mistral (REST API) | Grounded, concise, citation-backed answers |
| Scheduler | `code.scheduler` + GitHub Actions | Cron refresh that only rebuilds on real content change |

## Quickstart

```bash
# 1. Install dependencies
python3 -m venv .venv && source .venv/bin/activate   # optional but recommended
pip install -r requirements.txt

# 2. Configure
cp .env.example .env        # add your MISTRAL_API_KEY

# 3. Run the chatbot (index is already in data/chroma)
python3 -m code.ui
# opens http://localhost:8501

# 4. Inspect end-to-end answering from the CLI
python3 -c "from code.retrieval.retriever import answer_question;
import json; print(json.dumps(answer_question('What is the expense ratio of HDFC Large Cap?'), indent=2))"
```

> The repo ships with a pre-built index under `data/`. If you ever want a clean,
> from-source rebuild, follow the next section.

## Build the index from scratch

Each stage is a runnable module; run them in order:

```bash
python3 -m code.loading        # fetch 5 Groww pages -> data/raw
python3 -m code.chunking       # -> data/chunks
python3 -m code.embedding      # -> data/embeddings  (downloads MiniLM on first run)
python3 -m code.vector_store   # -> data/chroma (ChromaDB collection)
```

Or rebuild everything in one shot with the scheduler:

```bash
python3 -m code.scheduler --mode once --force
```

## Scheduler: keeping the corpus fresh

Fund pages change — expense ratios, benchmarks, `as on` dates, AMC notices.
The **scheduler** keeps the index honest by re-fetching the official pages and
**rebuilding only when the published content actually changed** (compared by
SHA-256 of the extracted text, so identical pages cause zero re-embedding and
zero git churn).

### CLI

```bash
# Check whether any page changed (writes nothing; exit 2 if changes available)
python3 -m code.scheduler --mode check

# Run a refresh now; rebuilds the corpus only if a page changed
python3 -m code.scheduler --mode once

# Force a full rebuild even if nothing changed
python3 -m code.scheduler --mode once --force

# Poll forever (default 24h) — for self-hosted servers, no API key needed for refresh
python3 -m code.scheduler --mode daemon --interval-hours 24
```

Exit codes: `0` ok/fresh, `1` failed, `2` check-mode with changes available.

### Automated weekly refresh (GitHub Actions)

`.github/workflows/refresh-corpus.yml` runs **every Monday 06:00 UTC** (and on
manual `Run workflow`): it installs dependencies, runs
`python3 -m code.scheduler --mode once`, and commits the refreshed
`data/` back to `main` **only if a page changed**. A rebuilt run also writes
`data/refresh.json` with the timestamp and per-stage results.

## Configuration

All configuration is environment-based.

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `MISTRAL_API_KEY` | Yes (for answers) | — | Mistral ask path |
| `MISTRAL_MODEL` | No | `mistral-small-latest` | Generation model |
| `REFRESH_INTERVAL_HOURS` | No | 24 | Scheduler daemon interval (CLI flag overrides) |

- **Local:** copy `.env.example` → `.env` (`python-dotenv` loads it).
- **Hugging Face Spaces:** set Space *secrets* (not just env vars).
- **Render:** declared in `render.yaml` (`sync: false` → set in dashboard).

## Deployment

The app is a standard Streamlit app, so it runs wherever Streamlit does.

### Hugging Face Spaces (primary)

1. Create a `New Space`, **Streamlit** SDK, keep `sdk_version: "1.62.0"` in the
   README front-matter (as configured in this repo).
2. Push this repo to the Space (either mirror-repo or use the Spaces SDK).
3. In **Settings → Secrets** add `MISTRAL_API_KEY`.
4. Open the Space — the app serves from `code/ui/app.py`.

### Render (free tier)

A blueprint is provided (`render.yaml`): it installs **CPU-only PyTorch**
first (to avoid CUDA wheels on the free tier), then runs
`python3 -m code.ui` with `--server.headless true`. Add `MISTRAL_API_KEY` in
the Render dashboard.

### Streamlit Community Cloud

Uses the top-level `streamlit_app.py` shim, which delegates to
`code/ui/app.py`. Works with a connected GitHub repo.

## Guardrails & Responsible AI

Guarded and enforced in code (`code/retrieval/gates.py` + `retriever.py`):

1. **PII protection** — PAN, Aadhaar, account numbers, OTPs, phone numbers and
   emails are masked **before** the query is embedded; nothing is stored or
   logged.
2. **No advice** — advice/recommendation and buy/sell language is refused with
   an educational reply (Groww's mutual-fund explainer link is provided).
3. **No returns/comparison** — return, CAGR, annualised and "which is better"
   phrasing is refused; the user is pointed to official factsheets instead.
4. **Empty/weak hits are refusals, not guesses** — below a similarity threshold
   the bot answers "I can't answer that from these five pages", even for
   questions about HDFC funds not in the corpus.
5. **Grounded generation** — Mistral only sees retrieved chunks, so answers
   cannot exceed the corpus; the citation is chosen, not invented.
6. **One source, one last-updated date** — transparency about what the answer
   came from and when the corpus was fetched.

## Data freshness & limitations

- **Freshness:** controlled by the scheduler (default weekly). `data/refresh.json`
  + the `last_updated` field on every answer record the last corpus refresh.
- **Scope:** only five HDFC **Direct Growth** funds on **Groww** — Large Cap,
  Flexi Cap, ELSS Tax Saver, Small Cap, Balanced Advantage.
- **Facts only:** no investment advice, no returns/comparisons, no financial
  planning — by design.
- **Corpus specificity:** facts shown on these pages, in English. Scheme
  documents/factsheets are not ingested, so some official details may not be
  retrievable.
- **No PII is accepted:** personal identifiers are redacted and never stored.
